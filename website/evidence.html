TRUST / VALIDATION / REPRODUCIBILITY

Trust is a process.
Not a label.

QuantLab makes input quality, evaluation boundaries, execution assumptions, and output identity explicit so research can be inspected and challenged.

DATA TRUST MODEL

Five machine-readable states.

Validation and trust are related, but not interchangeable. A structurally valid file does not automatically mean it is suitable for every research capability.

TRUSTED

Source quality is accepted for the declared capability, subject to the stated evidence.

CONDITIONALLY TRUSTED

Use is conditional; the reasons and supporting evidence remain explicit.

DEGRADED

Quality is impaired and requires careful interpretation; suitability is not presumed.

QUESTIONABLE

Data is not considered suitable by the current trust assessment.

UNRESOLVED

Validation failed or the trust status cannot be resolved for use.

The implementation evaluates capability suitability separately from the trust state and can enforce capability-specific allowed states. A trust gate is a data suitability control, not trading authorization.

CHRONOLOGICAL VALIDATION

Preserve the boundary.

Development and holdout data are separated chronologically. Warm-up rows can be retained to calculate rolling indicators, while signals before the evaluation boundary are neutralized.

The holdout workflow evaluates a fresh portfolio from the true OOS boundary and returns an evaluation equity curve beginning at that boundary. This helps avoid carrying a pre-holdout position into the evaluation.

Integrity is not provenance by itself.

A checksum establishes byte identity for the hashed file; it does not independently prove who originally created the data, whether the source was authoritative, or whether the strategy is valid. QuantLab's pilot specification calls for explicit source quality, dataset identity, code revision, configuration, rerun instructions, and human review before client-facing use.

REPRODUCIBILITY GUIDE

How to inspect and reproduce BTC #001.

1. Inspect the experiment definition

Start with the manifest and research report. They describe the experiment, evaluation boundaries, headline results, assumptions, and limitations.

2. Verify file integrity

Compare downloaded evidence files against the SHA-256 values in SHA256SUMS.txt. Matching hashes establish byte-level identity with the referenced files; they do not independently prove data provenance or research validity.

3. Inspect the evaluation outputs

Review the OOS summary, both equity curves, exposure summary, position events, regime summary, and individual regime episodes. Compare these records with the report and manifest.

4. Independently rerun the experiment

An independent numerical rerun requires the original historical BTC dataset, corresponding QuantLab implementation and code revision, and experiment configuration. Use the same chronological development and out-of-sample boundaries, frozen SMA20/SMA50 parameters, warm-up, execution convention, initial capital, position size, and transaction-cost assumptions. Compare the newly generated outputs with the published evidence and investigate discrepancies.

Experiment configuration

  • Asset and frequency: BTC daily data.
  • Strategy: long when SMA20 is above SMA50; otherwise flat.
  • Moving averages: fast 20, slow 50.
  • Development period ends: 22 December 2022.
  • Out-of-sample period: 23 December 2022 – 9 July 2026.
  • Out-of-sample observations: 1,295; warm-up: 50 bars.
  • Initial capital: 100,000; position size: 1.0.
  • Execution convention: one bar; base commission and slippage: zero.
  • Benchmark: buy-and-hold.

Reproduction limitations

The published evidence pack contains experiment outputs and supporting metadata, but does not include the original raw historical BTC dataset. An exact independent rerun therefore requires access to the same underlying data, its provenance, and the corresponding implementation and configuration.

The published cost sensitivity scenarios vary slippage while commission remains zero. They are not a complete real-world transaction-cost model. These historical results are not a future-performance guarantee or investment advice.

Interpretation

This study documents historical strategy behaviour and risk characteristics. It does not establish statistically significant return outperformance, future profitability, or robustness across other assets.
